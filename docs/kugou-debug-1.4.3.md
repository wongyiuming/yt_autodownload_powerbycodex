# 1.4.3：兼容个人歌单目录的 null 空页

## 已定位的问题

1.4.2 的脱敏诊断显示：`/v7/get_all_list` 第 2 页 HTTP 200、业务码 0，`data.info` 类型为 null，随后在 `rows` 检查处报 `INVALID_RESPONSE`。旧解析器的 `_first` 跳过 null，因而把明确的空页形式当作缺少列表字段，导致已读取的前页歌单无法成为可确认的预览。

这里只拿到了字段类型，未取得真实歌单内容、计数值或版本值。回归测试中的账号、token、标题、计数、版本和响应外层均为合成数据，不是用户账号数据。

## 修复范围

仅对已通过 HTTP、业务状态和账号校验的 `/v7/get_all_list` 响应，将明确存在且为 null 的 `info` 按空列表处理，再进入原有分页检查。不会在看到 null 时直接 return，也不会用 `value or []` 把字段缺失、空字符串、数字、布尔值或错误对象吞掉。

有非空备用列表字段时继续解析它，不因 `info:null` 提前结束；有异常的备用字段时仍拒绝响应。缺失列表字段仍报错。本次没有将兼容规则泛化到未获相同真实诊断的歌曲明细接口。

页码、总数、total_ver、has_more、重复页、安全上限、取消和认证检查全部保留：空页与明确总数/继续标记矛盾时仍不能完成预览。分类计数不相加作为 info 的权威总数。正常结束时保留此前累积的歌单、顺序和 URL。

Host 和扩展版本同步为 1.4.3，权限不变。只读预览不解析歌曲、不请求媒体、不创建下载任务，确认仍需同账号且一次性消费预览。

## 验证与使用

新增 `tests/test_kugou_null_page.py` 的 16 项回归：先在原始 1.4.2 上复现失败，再验证修复后的第 2 页 null、满页/短页后的继续请求、空库、备用字段、不完整响应、版本变化、认证失败、取消、重复页和只读预览确认边界。

安装对应提交的 Windows Actions 测试包，运行 `Install-Windows.bat`，重新加载固定目录中的扩展并确认 Host / 扩展都为 1.4.3，然后在已登录的酷狗主站点击“读取歌单 URL”。先核对歌单名称、数量和 URL，再手动确认下载。无需因本次诊断清除 Cookie 或重新登录。

修复已覆盖所报告的解析失败，但不代表真实账号全部歌单或歌曲下载已验收；真实账号复测仍由用户进行。正式 Release 与 PR 测试构建是不同渠道，未合并或发版不能视为正式发行。
