# 1.4.4：单曲/集合入口一致性与已下载文件复用

用户反馈同一首歌曲通过个人歌单集合成功下载，但单曲页下载返回“需要付费”。这不是当前账号权益的可靠结论；没有取得失败单曲的真实请求，不能宣称唯一根因或真实账号已验收。

## 代码修复

- 单曲网页、公开歌单和个人歌单统一使用 `_track_fields` / `_track` 规范歌曲字段，保留 hash、album_id、album_audio_id（mixsongid）、标题和时长，不再为个人歌单单独维护一套大小写别名。
- Python 与 JavaScript URL 规范化均保留单曲 hash 地址和 mixsong 地址中明确给出的歌曲标识；去除无关追踪参数。参数冲突或格式错误在请求播放接口之前报告，不扩大到个人库。
- mixsong URL 参数只补全页面缺失标识，不允许静默覆盖另一录音/专辑的已知标识。
- 网页播放请求传递已获得的 album_audio_id，不再解析后丢弃。同一个规范歌曲对象的播放请求与入口无关。保留原移动端回退链，不新增授权绕过、第三方解析或付费解锁。
- 单曲任务按完全相同的 hash 查找旧版 archive-audio.json 中的成功文件，复用到 `_单曲` 目录并明确显示复用状态。文件不存在仍重新解析下载；不按相同标题或猜测的 ID 复用不同歌曲，不覆盖冲突文件。
- 播放解析错误分别注明移动端/网页匿名接口，并标明这些是接口结果而非当前账号权益结论。不会只改日志把真实失败当成功。
- 空歌曲列表仅在预览数量明确为0或接口明确返回0总数时兼容 `info:null` / `info.file:null`；保留认证、账号、页码、总数、版本和结束标记检查。未知数量、缺失字段或矛盾数据仍失败。

## 验证边界

新增16项入口一致性回归和12项空歌单回归。与现有16项目录分页回归合并，本地44项通过；完整Windows CI以对应提交的构建结果为准。

无缓存用例验证相同歌曲经个人库、单曲网页和hash URL进入后发送相同播放参数。带缓存用例真实执行歌曲列表解析、合成媒体传输、归档及随后单曲任务，验证只追加页面元数据请求，不重复请求播放或媒体接口。旧版归档无需删除。

响应、歌曲和账号均为合成测试数据。没有登录用户账号，没有实测用户的失败单曲，也没有证明所有网页可播放资源均可下载；真实复测仍由用户完成。

字段关系参考 `zzstar101/MineRadio-api` 提交 `2f7196bedf02fd317a14d65cc1784045c685146b` 的 `src/providers/kugou/client.rs` 中 `song_url_web`：网页请求包含 hash、album_id 和 album_audio_id。本次只修复已有标识的保留/传递，不复制该项目的账号请求逻辑。

Host和扩展均为1.4.4。安装后重新加载固定目录的扩展，确认两端版本一致。无需重复登录、清空Cookie、删除历史下载或重新下载整个账号。
