# 1.4.5：单曲下载使用当前网页登录态

## 修复范围

1.4.4 的单曲入队、手动重试均强制匿名，Host 也只在个人歌单路径接收酷狗会话。字段兼容和已下载文件复用不能解决未缓存单曲的账号播放请求。本轮接通单曲 UI → 当前标签页会话 → Native Messaging → 内存绑定任务 → 官方网页播放接口的完整链路。

单曲页默认勾选“使用当前歌曲页面的酷狗登录状态”，可以取消后走既有匿名路径。勾选后会话读取失败必须在入队前报错，不静默降级为匿名。标签页 ID、歌曲规范化 URL 和读取前后导航状态必须一致；不借用另一个标签页的账号。重试重新读取会话，已绑定任务禁止换账号；历史匿名单曲可以明确选择登录态重试。

新增 `KugouSongClient` 仅用于勾选登录态的单曲。固定请求 `https://wwwapi.kugou.com/yy/index.php?r=play/getdata`，传递 hash、album_id、album_audio_id、appid、platid、mid、dfid、userid、token，并仅重建 KuGoo / kg_mid / kg_dfid 三种会话 Cookie。使用新建 HTTP Request，不继承客户端默认凭据。登录凭据不写入队列、归档或日志，不用于页面元数据、媒体 CDN 请求；认证请求拒绝重定向，不在认证失败后尝试匿名接口。

保留完整音频、试听和文件格式检查，不进行付费解锁或安全验证绕过。HTTP/业务失败仅显示固定文案及数字错误码，绝不回显原始响应或含凭据的 URL。认证失败不自动重试；普通暂时性错误沿用既有重试机制。任务结束、取消、移除时释放会话，Host 重启后未完成的登录态单曲需手动重新取得会话。

按本轮要求，不修改个人全部歌单或公开歌单的音频解析策略。用户报告的9首集合下载失败暂不归因、不作已修复声明；这份日志的匿名失败不能证明登录账号的付费权限不足。1.4.4 的空歌单修复、统一标识、缓存复用继续保留。

## 测试

新增真实 Python/JavaScript 代码的合成回归：无归档首次下载必须经过登录态播放请求；CDN 和元数据无 Cookie/token/Authorization；拒绝会话不降级；重定向、安全验证、错误响应脱敏；同账号重试、账号切换、退出后的恢复、会话清理；实际 background/popup 处理器的默认勾选、取消勾选、标签页绑定和个人库行为隔离。Node 子进程使用 UTF-8。

本地缺少仓库固定版本的 yt-dlp，因此本地仅对无关 YouTube 导入使用占位运行这些隔离测试，未冒充全量回归。完整依赖、全量测试、冻结 EXE、安装器及 Native Messaging 由 Windows CI 验证。所有账号与媒体数据均为合成；用户真实账号端到端验收仍未执行。

## 安装与验证

Host 与扩展同步1.4.5，权限不变。运行对应 Windows 安装包的 Install-Windows.bat，再重新加载固定安装目录的扩展。回到已登录的单曲页面，重新“读取当前页”，保持登录态选项勾选并创建新单曲任务。无需删除已下载文件、归档或重新下载整个个人库。若仍失败，应显示“酷狗网页登录态播放接口……”而不是“移动端匿名接口……”，据实际响应继续定位。
